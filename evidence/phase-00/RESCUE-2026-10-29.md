## 2) إصلاح CI قبل التفعيل (تغيير واحد مبرَّر)

القالب في PR #5 كان يربط وظيفة القياس بنجاح كل وظيفة اختبارات الوحدة
(`eval: needs: unit`)، فأي فشل في اختبار قديم واحد من الـ 452 كان سيمنع ظهور
أي رقم خط أساس. التعديل في `ci/github-actions.yml`:

- `eval: needs: preflight` — يقيس ويتوازى مع `unit` وينتج دليله على أي حال.
- `apk` ينتظر انتهاء `eval` لكنه يعمل حتى لو فشلت (`if: always() && needs.preflight.result == 'success'`)،
  وتنزيل artifact النتائج `continue-on-error`، وغياب `results.json` لا يُفشل بناء الـ APK
  (يُبنى بلا `eval_summary.json` ويُظهر زر «تشخيص» ذلك).
- لا إخفاء للفشل: أي وظيفة فاشلة تُبقي الـ workflow أحمر.

ثم **حاولت** تنشيط الـ CI بأداة المشروع نفسها: `./scripts/install_ci.sh`
(`ci/github-actions.yml` ← `.github/workflows/ci.yml`، ملفان متطابقان بُتحقق منهما محليًا)،
لكن GitHub رفض الدفع — نفس حاجز PR #5 الأصلي:

```text
! [remote rejected] arena/6098bee0-zahra -> arena/6098bee0-zahra
  (refusing to allow a GitHub App to create or update workflow
   `.github/workflows/ci.yml` without `workflows` permission)
# والـ Contents API ردّت كذلك: 403 Resource not accessible by integration
```

لذا حُذف `.github/workflows/ci.yml` من الكوميت وبقي القالب في `ci/github-actions.yml`.
**التفعيل خطوة واحدة بصلاحية مالك المستودع:** `./scripts/install_ci.sh --commit && git push`
(على هذا الفرع قبل الدمج لتظهر الفحوصات على الـ PR، أو على `main` بعد الدمج).
