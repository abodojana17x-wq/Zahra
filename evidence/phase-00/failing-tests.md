# الاختبارات الفاشلة — سياسة التصنيف (D6) والقالب الجاهز

**الحالة الآن:** لم يُشغَّل `./gradlew :app:testDebugUnitTest` بعد في هذه البيئة (لا JDK/SDK — انظر [`README.md`](README.md) §2/§3). لذلك **لا يوجد جدول فاشلين مزعوم**، والقالب أدناه يُملأ حرفيًا من أول تشغيل في CI.

---

## السياسة (ملزمة قبل لمس أي اختبار)

القاعدة **D6**: «إصلاح وتشغيل 452 وسم `@Test`؛ أي اختبار لا يُصلح في المرحلة 0 يُحذف بقرار موثق».

1. **لا يُحذف اختبار لأن نتيجته مزعجة.** الحذف مسموح فقط لسبب تقني/تصميمي مكتوب (صنف من الأصناف أدناه) ومراجَع.
2. **لا تُعدَّل توقعات مجموعة القياس** (`eval/*.jsonl`) بعد رؤية النتائج. أي تعديل = إصدار v2 + إعادة قياس (القاعدة 2).
3. كل صف في الجدول يلزمه: اسم الاختبار الكامل، صنفه، سبب الفشل الحقيقي (اقتباس من السجل)، القرار، والـ commit.
4. أي اختبار يُعدَّل ليمر: **يُذكر في جدول «تعديلات الاختبار»** مع سبب أنه تصحيح خطأ في الاختبار لا تخفيف توقع. هذا هو الفرق بين الإصلاح والغش.

## أصناف التصنيف (لا صنف سادس بلا تعديل هذا الملف)

| الصنف | التعريف | القرار الافتراضي |
|---|---|---|
| `compile_error` | الكود لا يُترجم (مرجع لنوع/دالة غير موجودة) | إصلاح؛ لو كان نوعًا محذوفًا عمدًا → حذف الاختبار مع قرار |
| `robolectric_config` | فشل تهيئة بيئة أندرويد (أصول/أذونات/SDK) | إصلاح (`robolectric.properties`، `isIncludeAndroidResources`) |
| `assertion` | الاختبار يعمل لكن التوقع لا يتحقق | تحليل: هل الكود خطأ أم التوقع خطأ؟ يُسجَّل القرار صراحةً |
| `flaky` | نتيجة متغيرة بين تشغيلين (عشوائية/وقت/خيوط) | إما تثبيت البذرة/الوقت أو حذف مع نقل الحالة إلى `eval/` كحالة قياس |
| `obsolete` | يختبر سلوكًا أُزيل/تغيّر عمدًا في الخطة | حذف مع ذكر القرار البديل (المرحلة التي تغطي السلوك الآن) |
| `environment` | يحتاج جهازًا/خدمة خارجية (Emulator، شبكة) | نقل إلى `androidTest` أو وسم `@Ignore` **مع سبب مكتوب** |

## كيف تُملأ آليًا؟

```bash
./gradlew :app:testDebugUnitTest --no-daemon 2>&1 | tee evidence/phase-00/gradle-test.log
python3 - <<'PY'
# يسحب الفاشلين من تقرير JUnit XML ويطبع صفوفًا جاهزة للصق
import glob, xml.etree.ElementTree as ET
for f in glob.glob('app/build/test-results/testDebugUnitTest/*.xml'):
    for tc in ET.parse(f).getroot().iter('testcase'):
        for fail in list(tc.iter('failure')) + list(tc.iter('error')):
            print(f"| {tc.get('classname')}.{tc.get('name')} | assertion | {(fail.get('message') or '')[:120]} | ؟ | ؟ |")
PY
```

> بعد كل تشغيل: لا تُغلق المرحلة 0 وبها صنف `environment` بلا قرار، ولا صنف `flaky` بلا نقل الحالة إلى `eval/`.
