# بروتوكول التقييم والقياس — المرحلة 6

> هذا البروتوكول **لم يُنفَّذ**. القالب في [`release/blind-protocol.example.json`](../release/blind-protocol.example.json)
> حالته `template-not-run`، ولا يصلح لنشر نتيجة قبل توقيعه وتجميده. الغرض هنا منع
> «القياس بعد معرفة النتيجة» ومنع نشر نسبة بلا فاصل ثقة أو بلا إفصاح عن التحيّز.

## مبادئ غير قابلة للتفاوض

1. **المجموعة مجمّدة** (`eval/MANIFEST.sha256`). held-out لا يُستخدم في التطوير ولا
   في ضبط العتبات ولا في اختيار الأمثلة.
2. **التسجيل المسبق** قبل جمع أي صوت أو رؤية أي مخرج.
3. **لا قياس بلا مخرجات خام**؛ الأصوات والجدول والبذرة تُحفظ.
4. **لا حذف للفشل**: كل حالة تُنشر، بما فيها `skipped` وأسبابها.
5. **لا رقم بلا فاصل ثقة** وحجم عينة، ولا Elo وحده كدليل.

## التسجيل المسبق

قبل أي تشغيل، تُنسخ [`release/blind-protocol.example.json`](../release/blind-protocol.example.json)
إلى ملف خاص بالجولة (مثلاً `release/protocols/2026-11-blind-v1.json`) ويُملأ:

| الحقل | المطلوب |
|---|---|
| `protocolId` | معرّف فريد للجولة |
| `status` | `preregistered` قبل البدء (لا `complete`) |
| `preregisteredAt` | تاريخ/وقت UTC |
| `preregisteredBy` | شخص/جهة مسؤولة، لا «الوكيل» |
| `dataset.sha256` | هاش `eval/held-out.jsonl` في وقت التسجيل |
| `systems` | نظامان محددان بإصدار/commit |
| `design.judges` | ≥ 2 للاتفاق (3 مستحسن) |
| `design.randomizationSeed` | عدد صحيح معلن |
| `endpoints.primary` | واحد فقط قبل البدء |
| `analysis` | alpha، bootstrap، Holm، وحدة إعادة الأخذ |
| `stoppingRule` | حجم ثابت؛ لا إيقاف اختياري |
| `exclusions` | تعريف مسبق للمفقود/غير الصالح |

أي تعديل بعد بدء الجمع يُسجَّل كتعديل مؤرخ مع أثره، ولا يُعاد ترتيب النتائج تحته.
تغيير النهاية الأساسية بعد رؤية البيانات = جولة جديدة، لا تعديل.

### عينة وطاقة

- العينة الافتراضية: 50 حالة held-out × عرضان × كل المحكّمين.
- العينة صغيرة: الفاصل سيكون واسعًا، وهذا يُنشر لا يُخفى.
- لا «إضافة حالات حتى الدلالة». إذا لم تكن الفروق دالة، هذا نتيجة.
- أي تحليل مجالات فرعي يُعد **استكشافيًا** إلا إذا كان مسجلًا كأساسي.

## العمى وتبديل الموضع

### تصميم العروض

لكل حالة:

1. عرضان متوازنان: `(زهرة A، خط الأساس B)` و`(خط الأساس A، زهرة B)`.
2. خلط ترتيب العروض ببذرة معلنة (`--seed`).
3. المحكّم يرى **A/B فقط** بلا أسماء أنظمة ولا ألوان تمييز ولا ترتيب ثابت.
4. لا محكّم يعرف أي نظام بنى الإجابة، ولا يرى إجابته المفضلة السابقة.
5. التعليمات تُعطى قبل رؤية المخرجات، مع 3 أمثلة معيارية خارج held-out.

### معالجة التحيّزات المعروفة

| التحيّز | الضابط |
|---|---|
| تحيّز الموضع (primacy/recency) | تبديل كامل + قياس `position_consistency` ونسبة فوز الموضع الأول |
| تحيّز الطول/التنسيق | تعليمات بعدم تفضيل الطول، وتحليل وصفي لطول الإجابات، وعدم اعتبار الطول ميزة |
| تحيّز التفضيل الذاتي (نظام يحكم على نفسه) | محكّمون بشريون مستقلون؛ لا يستخدم أي نظام محكّم لنفسه |
| تحيّز المحكّم/الانحياز الشخصي | ≥ 3 محكّمين، kappa، ونشر الأصوات الخام |
| تسريب هوية/تلميح | تعمية الأسماء والأوصاف؛ استبعاد المحكّم الذي يعرف الهوية |
| التحيّز الثقافي/اللهجي | توثيق خلفية المحكّمين، وعدم تعميم النتيجة على كل اللهجات |

### معايير المحكّم

- مستقل عن تطوير زهرة ومحتواها (لا كاتب أسئلة، لا مصحح نظام).
- يوقّع إقرار عدم معرفة هوية النظامين.
- لا يحكم على حالات درّب عليها أو راجعها.
- يُستبعد كاملًا إذا خالف العمى، ويُنشر الاستبعاد وسببه.

## المتغيرات والنتائج

### النهاية الأساسية

`pairwise_preference_win_rate`:

\[
\text{half-win rate} = \frac{W + 0.5T}{W + L + T}
\]

حيث `W` فوز النظام، `L` خسارته، `T` تعادل. التعادل يُحسب نصفًا (معلن مسبقًا)،
والأصوات `invalid` تُستبعد وتُنشر نسبتها. يُقدّم الفاصل الرئيسي بـ**bootstrap
عنقودي** على مستوى الحالة (لأن أصوات نفس الحالة مترابطة).

### نهايات ثانوية

- `position_consistency` مع Wilson 95%.
- `first_position_win_rate` مع اختبار ثنائي ذيليين مقابل 0.5.
- اتفاق المحكّمين: Cohen kappa لكل زوج، وFleiss kappa الكلي.
- Bradley-Terry: قوة نسبية وفرق log-strength مع bootstrap عنقودي.
- McNemar على `passed` إذا توفرت نتائج تشغيل لكل نظام على نفس الحالات.
- Elo **ثانوي فقط**، ويُذكر أنه يعتمد على ترتيب الأصوات.

### ما لا يُعد نهاية أساسية

- متوسط طول الإجابة.
- انطباع نوعي بلا معايير.
- نسبة «إجابات صحيحة» على حالات لم تُقيّم إلا بمحكّم واحد.
- أي رقم مُستخرج بعد رؤية النتائج.

## التحليل الإحصائي

### فترات الثقة

- **Wilson** لنسبة ثنائية (لا Wald) لأن العينة صغيرة والنسب قد تقترب من 0/1.
- **bootstrap percentile** للوسيط والفرق، مع ≥ 1000 إعادة (الافتراضي 10,000
  في البروتوكول، و2000 في أداة التحليل السريع).
- **bootstrap عنقودي** على مستوى الحالة، لا الصوت المفرد.
- كل فاصل يُنشر بجانب العدد المطلق، لا النسبة وحدها.

### اختبار الفروق

- **McNemar الدقيق** (ذيليان) لنتائج `passed` الزوجية: `b` = فشل A ونجاح B،
  `c` = نجاح A وفشل B، و`p` من توزيع ثنائي.
- **Bradley-Terry (MM)** لاحتمالات التفضيل، مع تحويل التعادل إلى نصف فوز.
- **Holm–Bonferroni** عند تعدد المجالات/النهايات الثانوية المعلنة.
- لا اختبار t على نسب ثنائية صغيرة، ولا chi-square تقليدي بلا تصحيح.
- تُنشر `p` مع الفاصل وحجم العينة؛ `p < 0.05` وحده ليس «نجاحًا».

### المفقود والاستبعاد

| الحالة | المعالجة | الإفصاح |
|---|---|---|
| عرض بلا صوت | مفقود، لا يُخترع | عدد ونسبة |
| صوت `invalid` | مستبعد من النسبة | عدد ونسبة |
| فشل تقني لنظام في عرض | خسارة ذلك العرض مع سبب | كل الحالات |
| محكّم خالف العمى | استبعاد كامل | عدده وسببه |
| حالة `skipped` | مستبعدة من النسبة | عدّها وسببها |
| تعادل | نصف فوز حسب التسجيل | عدد التعادلات |

### التعدد والشفافية

- تُنشر كل النهايات المسجلة، لا الناجحة فقط.
- لا «metric shopping» ولا تغيير alpha بعد النظر.
- تُنشر البذور وأوامر التشغيل وهاش الملفات.
- تُنشر حدود العينة والطاقة؛ عدم الدلالة لا يعني «لا فرق» قطعًا.

## المقارنة مع نموذج سحابي

- المقارنة **غير متكافئة بنيويًا** (شبكة/حجم/تدريب مقابل جهاز/Zero-LLM).
- تُنشر كسياق على مهام محددة، لا كـ«ذكاء عام».
- أي لقطة من نموذج خارجي تحتاج تاريخًا وإصدارًا وشروط استخدام (D14).
- لا تُنسخ إجابات نموذج سحابي إلى حزم المنتج (D5/D31).

## إعادة الإنتاج

```bash
# 1. التحقق من البروتوكول والمجموعة
python3 tools/phase06/blind_bench.py validate-protocol --protocol <protocol.json>

# 2. جدول العروض
python3 tools/phase06/blind_bench.py schedule --cases eval/held-out.jsonl \
  --systems zahra baseline --seed <seed> --out build/phase06/schedule.jsonl

# 3. التحليل بعد جمع الأصوات
python3 tools/phase06/blind_bench.py analyze --schedule build/phase06/schedule.jsonl \
  --votes <votes.jsonl> --target zahra --ref baseline \
  --out build/phase06/analysis.json --markdown build/phase06/analysis.md

# 4. مقارنة نتائج التشغيل إن وجدت
python3 tools/phase06/blind_bench.py compare-results --a <a/results.json> \
  --b <b/results.json> --label-a <A> --label-b <B> --out build/phase06/compare.json
```

الأداة لا تنشئ أصواتًا ولا تشغّل المحكّمين. ملف الأصوات يجب أن يكون خامًا
(`presentation_id`, `judge_id`, `verdict`) ولا يُعدّل بعد التحليل.

## ما لا يُدَّعى

- لا «تفوق» عام على GPT/Claude/Grok/Gemini/DeepSeek من 50 حالة.
- لا «دقة 100%» ولا نسبة بلا فاصل ولا نتيجة على مجموعة غير مجمدة.
- لا تعميم على لهجات أو أجهزة أو مجالات لم تُختبر.
- لا «تحسّن» بعد تغيير الكود دون إعادة تشغيل على نفس الحالات.
- لا اعتبار أدوات الإحصاء نفسها دليلًا؛ الأداة الصحيحة مع مدخلات مختلقة = نتيجة مختلقة.
- لا استنتاج أن غياب الثغرة في الاختبار يعني الأمان؛ راجع [الأمان](SECURITY.md).
