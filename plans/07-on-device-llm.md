## 1. الفكرة المحورية (سقف طريقة المنافس → تطوير زهرة)

خطة المنافس قالت حرفيًا:

> «لو عايز حوار حر حقيقي (كتابة إبداعية، تلخيص، ترجمة، استدلال طويل)، لازم نموذج توليدي ولو صغير على الجهاز. ده خارج شرطك، لكن ممكن يتضاف لاحقًا كـ "وضع متقدّم" اختياري من غير ما يمس النواة.»

زهرة عندها ميزة تنافسية لا يملكها ملف HTML: **معالجة محلية حقيقية على أندرويد** (OCR، TTS، تخزين مشفر، NPU على الأجهزة الحديثة). المرحلة 7 تستغل هذا لتضيف:

```
المستخدم يفعّل «الوضع المتقدم» (Opt-in)
   ↓
AdvancedModeGate: هل النموذج محمّل؟ هل الجهاز يكفي؟ هل الطلب من النوع التوليدي؟
   ↓
GroundedGenerator: يسترجع من فهرس المرحلة 3 → يبني prompt بمصادر → يولّد بقيود → يتحقق
   ↓
ConfidenceGate + ResponseValidator (نفس بوابة المرحلة 1) → رد بمصدر، أو امتناع
   ↓
أي فشل/بطء/هلوسة → Fallback فوري للنواة الحتمية (0–6)
```

**الهدف المعلن:** تقليص الفجوة مع النماذج الكبرى في: المحادثة الحرة، التلخيص، إعادة الصياغة، الكتابة الإبداعية القصيرة، وشرح الكود — **مع الحفاظ على 100% من مكاسب الصدق والأدوات**.

## 2. مسارات العمل

### المسار A — سجل النماذج والقرار (D10/D11)

1. `advanced/ModelRegistry.kt`: كل نموذج مرشح بـ `id, family, params, quant, sizeMB, licenseUrl, arabicScore, licenseAllowsCommercial, minRamMB, sourceUrl`.
2. **معايير قبول أي نموذج قبل التنزيل:** ترخيص يسمح بالتوزيع داخل تطبيق، حجم مكمّم ≤ ميزانية D7، RAM ≤ 2GB على جهاز متوسط، ودرجة عربية/مصرية مقاسة على 50 سؤال من `frontier-set`.
3. **طريقة التسليم (D11):** الخيار المفضل = تنزيل عند الطلب من رابط ثابت + تحقق من `sha256` + تخزين مشفر + إمكانية الحذف؛ لا يُضمّن وزن كبير داخل APK الأساسي. أي تنزيل = Opt-in صريح، ويُسجّل في واجهة الخصوصية.
4. **قائمة سوداء:** أي نموذج يتطلب اتصالًا بالسحابة وقت الاستدلال = مرفوض (ينتهك Zero-Network).

### المسار B — طبقة التشغيل (`advanced/SlmRuntime.kt`)

1. واجهة واحدة خلف وقت التشغيل المختار: `load(model)`, `generate(prompt, grammar, maxTokens, budgetMs)`, `cancel()`, `unload()`, `capabilities()`.
2. **ميزانية صارمة:** `maxTokens` افتراضي 256، مهلة زمنية `budgetMs` قابلة للضبط، وإلغاء فوري عند خروج المستخدم من الشاشة (تجنّب استنزاف البطارية).
4. **تدهور رشيق:** لو RAM غير كافٍ أو `TTFT > 3s` → يعود للنواة الحتمية برسالة صادقة («الوضع المتقدم مش متاح على جهازك دلوقتي، رديت لك بالإجابة الموثقة»).

### المسار C — التوليد المُؤسَّس (`advanced/GroundedGenerator.kt`)

1. **لا توليد بلا سند:** يستدعي `HybridRetriever` (المرحلة 3) أولًا؛ أعلى 3 وحدات تُحقن في الـ prompt مع `sourceUrl` و`license`.
2. **قيود إخراج:** قواعد/JSON schema للردود اللي فيها حقائق؛ أي رقم أو رابط لازم يكون موجودًا في السياق المسترجع، وإلا يُحذف أو يُستبدل بامتناع.
3. **`ConfidenceGate` ما زال الحاكم:** لو استرجاع < العتبة → لا يُستدعى النموذج أصلًا في أسئلة الحقائق (يوفر الوقت ويمنع الهلوسة). النموذج يُستخدم فقط في المهام التوليدية الصرفة (تلخيص، إعادة صياغة، كتابة، شرح).
4. **فاحص ما بعد التوليد:** إعادة فحص الرد مقابل `ResponseValidator` + فحص تناقض مع المصادر + كشف «ذاكرة وهمية» (المرحلة 4) + منع الفتوى/الوصفات الطبية.
5. **وسم شفاف:** كل رد من الوضع المتقدم يظهر فيه «مولّد محليًا • مدعوم بالمصادر: …»، ويعرف المستخدم أي رد جاي من النواة وأي رد جاي من النموذج.

## 5. المخاطر والتخفيف

| الخطر | التخفيف |
|---|---|
| النموذج يهلوس ويُفسد سمعة الصدق | توليد مؤسّس + قيود + فاحص بعد التوليد + بوابة الثقة قبل الاستدعاء |
| حجم النموذج يقتل التحميل على أجهزة ضعيفة | تنزيل عند الطلب + تدهور رشيق + مراجعة توافق API 24 |
| ترخيص الأوزان لا يسمح بالتوزيع | فحص ترخيص إلزامي في `ModelRegistry` قبل أي تنزيل (D10) |
| استنزاف البطارية/الحرارة | ميزانية توكنات + مهلة + إلغاء + مهلة تشغيل مناسبة |
| تعارض فلسفي مع Zero-LLM | الوضع المتقدم **اختياري ومعزول**؛ النواة تُقاس بدونه  |
| العربية/المصري ضعيفة في النماذج الصغيرة | RAG بمحتوى عربي + توثيق القيود دون شرط قبول رقمي |
