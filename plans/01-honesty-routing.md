## 1. الفكرة المحورية

خطة المنافس: «الموجّه يحدد نوع السؤال قبل البحث في الـ KB، وبوابة الثقة تحت حد معين = مش متأكد، تقصد X ولا Y؟». زهرة عندها نفس الفلسفة نظريًا (`CalibratedClassifier`, `EpistemicGroundingPipeline`, `ResponseValidator`) لكن **القرار مبعثر** في `ZahraRouter`:

- `calibratedScore.topProbability >= 0.50`
- `nbScore.confidence < 0.40`
- `confidence < 0.45` / `< 0.85` / `< 0.70` في فروع مختلفة
- `ReligionEngine`: `bestScore >= 0.40` و`score < 0.30`
- `generateFallback()` يرد امتناعًا صريحًا — وهذه نقطة قوة نحافظ عليها.

**المطلوب:** تحويل هذا التشتت إلى **قرار واحد موحّد** (`RoutingDecision`) مع تتبّع كامل لكل سؤال: `(normalized → intent → confidence → route → gate → outcome)`. ثم يصبح كل تحسين لاحق قابلًا للقياس والتصحيح بدون لمس عشرات الفروع.

## 2. مسارات العمل

### المسار A — خريطة القرار الحالية (توثيق قبل التعديل)

1. أنشئ `evidence/phase-01/router-decision-map.md`: جدول بكل فرع في `ZahraRouter.process()` يشترط confidence، مع رقم السطر والقيمة والنية.
2. صنّف كل فرع: `يُبقى` / `يُستبدل بالبوابة` / `يُحذف`، واذكر الاختبار الذي سيغطيه.
3. اكتب اختبارات Characterization للسلوك الحالي (حتى تعرف ما كسرته).

### المسار B — طبقة التطبيع (مصري + فرانكو-عرب + تشكيل)

1. وسّع `ZahraNormalizer` (الموجود فيه `francoToArabic` و`normalize` و`extractWords`):
   - قاموس فرانكو مركّب (عبارات قبل الكلمات): `3amel eh`, `3ayez a3raf`, `how are you`, `good morning` … مستوحى من `FRANCO_PHRASES` في `reference/raqim-2.0.html`.
   - قاموس مفردات ≥ 300 مدخل (`ezay/azzay/izzay → ازاي`, `3ayez/a3raf`, `keda/kda`, `delwa2ty`, `leh`, `fen`, `mesh`, `khalas` …).
   - توحيد الهمزات/التاء المربوطة/الألف المقصورة/التشكيل + أرقام عربية/هندية.
   - تجذيع خفيف للعربية (حذف `ال`, `و`, `ب`, `ل`, `ة`, `ي` زائدة) مع **قائمة استثناءات** حتى لا يتحوّل «البرمجة» و«برمجة» لمفتاحين مختلفين خطأً.
2. `LanguageDetector` حاليًا يكتشف الفرانكو بـ ~18 كلمة فقط: اربطه بالقاموس الجديد وأضف درجة ثقة بدل قرار ثنائي، مع اختبارات لأنواع الجمل المختلطة (عربي + إنجليزي + أرقام).
3. **قاعدة ذهبية:** التطبيع لا يغيّر معنى السؤال. أي تحويل لازم يكون له اختبار `normalize(input) == expected`.

### المسار C — الموجّه الموحّد (`routing/`)

```
data class RoutingDecision(
  val raw: String, val normalized: String, val detectedLang: DetectedLang,
  val intent: Intent, val scores: Map<String, Double>, val confidence: Double,
  val route: Route,           // CALC | UNIT | TIME | FACT | CODE | SOCIAL | EMOTION | RELIGION | SYSTEM | REFUSE
  val gate: GateOutcome,      // ANSWER | CLARIFY | ABSTAIN
  val clarifyOptions: List<String>, val traceId: String
)
```

1. ترتيب الأولوية صريح وموثق: **أمان/رفض → أوامر النظام (مهام/ملاحظات/منبهات) → أدوات حتمية (حساب/وحدات/وقت) → حقائق بمصدر → برمجة → دين → مشاعر/حوار → امتناع**.
2. افصل قرار التوجيه عن التنفيذ: `Router` لا يبني ردًا، يُعيد `RoutingDecision`؛ `ZahraRouter` ينفّذها. هذا يسمح باختبار التوجيه بدون Robolectric ثقيل.
3. أزل الـ `confidence` الثابتة (0.98/0.99) التي تُكتب يدويًا في كل فرع؛ القيمة لازم تيجي من المصدر الحقيقي (أداة/استرجاع/مصنّف).
4. أتح `traceId` في قرار التوجيه لتشخيص المراحل اللاحقة؛ لا يُشترط إنتاج تقرير قياس.

### المسار D — بوابة الثقة (`ConfidenceGate`)

1. افصل سياسة حدود الثقة لكل نية عن التنفيذ (D4). المعايرة ليست شرط إكمال؛ لا تختلق قيمًا مُعايرة أو تكتب عتبات جديدة بلا قياس فعلي. عند غياب القياس، وثّق أن المعايرة غير منفّذة.
2. ثلاث مخرجات فقط:
   - `ANSWER` — فوق العتبة وله مصدر/أداة.
   - `CLARIFY` — «مش متأكد، تقصد X ولا Y؟» مع 2–3 بدائل **مأخوذة من أعلى 3 نيات فعلية**، لا من كلمة عشوائية في السؤال.
   - `ABSTAIN` — امتناع صريح (مثل `generateFallback` الحالي) بدون أي كلمة من سؤال المستخدم.
3. `ResponseValidator` يصبح آخر خط: يمنع أي رد يحتوي على أنماط «ما زال في ذاكرتي/كما ذكرت سابقًا/رقيمي» إلا إذا وُجد turn حقيقي (المرحلة 4 ستُكمل المنع، هنا تضع الحاجز الأول).

## 5. المخاطر والتخفيف

| الخطر | التخفيف |
|---|---|
| رفع العتبة يقتل التغطية (يمنع كل حاجة) | معايرة لكل نية + قياس «الامتناع الكاذب» صراحةً في التقرير |
| التطبيع يدمج كلمات متضادة | تجذيع محافظ + قائمة استثناءات + اختبارات أزواج دنيا |
| إعادة هيكلة Router تكسر 85 ملف يعتمدون عليه | Characterization tests أولًا + واجهات خلف نفس التوقيع + مراجعة تزايدية |
| «البدائل» في CLARIFY تبدو عشوائية | تُؤخذ من أعلى 3 نيات بالمصنّف المعاير فقط |
