## 1. الفكرة المحورية

المنافس يتفوق بوضوح في الحساب والوحدات: **27/27 حساب، 12/12 وحدات، 5/5 وقت**، مقابل 10 أزواج وحدات مثبتة في زهرة (`kg↔lb`, `km↔mi`, `c↔f`, `m↔ft`, `l↔gal`). هذه هي أسهل نقطة يمكن لزهرة أن تتفوق فيها لأنها **لا تحتاج نموذجًا لغويًا أصلًا**: تحتاج هندسة صحيحة.

الفرق الجوهري عن خطة المنافس: على أندرويد لا نستطيع استخدام `math.js`/Nerdamer/Pyodide مباشرة. البديل:

```
نص عربي → تطبيع (المرحلة 1) → استخراج تعبير → Lexer → Parser (Pratt / recursive descent)
       → قيمة + وحدة → تنسيق عربي → رد بمصدر «محرك الحساب الدقيق» (confidence=1.0)
```

## 2. مسارات العمل

### المسار A — محلّل رياضي كامل (`math/MathParser.kt`)

1. **Lexer:** أرقام عربية `٠-٩` و`0-9`، كسور، أس `^`، معاملات `+ - * / %`، أقواس، فاصلة، معرّفات (دوال/ثوابت)، ضرب ضمني (`2(3+4)`, `3pi`, `2sqrt(9)`).
2. **Parser:** أولوية العمليات، ترابط، دالات متعددة الوسائط، إغلاق أقسام، و**رفض صريح** لأي معرّف غير معروف (مثل `process.exit`, `alert`) — اختبارات أمان من `selfTest` عند المنافس.
3. **≥ 20 دالة:** `sqrt, abs, sin, cos, tan, asin, acos, atan, log, log2, ln, exp, floor, ceil, round, trunc, sign, cbrt, pow, min, max, sum, avg, gcd, lcm, fact` + ثوابت `pi, e, phi`.
4. **أسماء عربية:** `جذر→sqrt`, `الجذر`, `جيب→sin`, `جتا→cos`, `ظل→tan`, `مطلق→abs`, `لوغاريتم→log`, `لن→ln`, `باي→pi`, `مضروب→fact`.
5. **حالات حدية إلزامية:** قسمة على صفر، جذر سالب، طفحان رقمي (`NaN/Inf`), تعبير ناقص، أقواس غير متوازنة، إدخال فارغ، أرقام مختلطة، `2^-3`, `!!` (مضروب مزدوج يُرفض بوضوح).
6. احتفظ بواجهة `MathEngine.evaluate()` الحالية (التوافق مع 85 ملف) لكن اجعلها Delegating إلى المحلّل الجديد؛ لا تكسر `MathResult` ولا `OutcomeState`.
7. **مصدر المعلومة:** كل رد حسابي `source = "محرك الحساب الرياضي الدقيق"`, `confidence = 1.0`, و`executionTrace` يحتوي التعبير المُطبع + شجرة العمليات (مفيد للتصحيح والقياس).

### المسار B — نظام وحدات عام (`math/UnitSystem.kt`)

1. استبدل الـ `when` ذا العشرة فروع بـ **جدول عوامل** لكل تصنيف (9 تصنيفات):
   - طول (mm, cm, m, km, inch, ft, yd, mi), كتلة (mg, g, kg, ton, oz, lb), حرارة (C, F, K — **تحويل أفيني** مش عامل ضرب), حجم (ml, l, gal, cup), مساحة (m², cm², km², فدان, متر مربع ← فدان = 4200.83 m²), زمن (ms, s, min, h, day, week), سرعة (km/h, m/s, mph), بيانات (bit, B, KB, MB, GB), عملة (مع **تحذير صريح**: أسعار ثابتة قديمة أو تتطلب مصدرًا حيًا — لا تُستخدم في رد جازم).
2. التحويل: `value → base → target` مع دعم الأس (`km² → m²`) والتحويلات الأفينية (`C ↔ F ↔ K`).
3. دعم **أي زوج داخل التصنيف** (المنافس يفتخر بـ «3 فدان إلى متر مربع») + أسماء عربية (`كيلو`, `كيلومتر`, `رطل`, `فدان`, `لتر`, `جنيه`).
4. رفض التحويل بين تصنيفات مختلفة برسالة تعليمية («مفيش تحويل بين كتلة وطول»)، لا برقم عشوائي.
5. ≥ 60 اختبار تحويل + اختبارات عكسية (`A→B→A == الأصل`).

### المسار C — المسائل الكلامية المصرية (`math/WordProblems.kt`)

قوالب قابلة للاختبار (مع أمثلة من تقرير المنافس):
`«500 وخصم 20%» → 400`, `«20% من 500» → 100`, `«متوسط 4 و8 و10» → 7.333`, `«مساحة دائرة نص قطرها 5» → 19.635`, `«اشتريت 3 حاجات بـ 25 جنيه وخصم 10%»`, `«لو معايا 1000 وصرفت 350 كام يفضل»`.

**قاعدة:** أي قالب جديد لازم له اختبار + حالة سلبية (جملة شبيهة لكن المقصود مختلف → يُترك لل router ولا يُحسب بالغلط).

### المسار D — الوقت والتاريخ الهجري (`tools/TimeTools.kt`)

1. `minSdk = 24` → لا تفترض توفر `java.time` مباشرة. استخدم **`android.icu.util.IslamicCalendar`** (متاح من API 24) أو فعّل `coreLibraryDesugaring` بعد قياس أثره على الحجم. سجّل القرار في `DECISIONS.md`.
2. دعم: «النهاردة/بكرة/أمبارح/الساعة كام/التاريخ الهجري/كم يوم للجمعة» + مناطق زمنية +Relative dates قابلة للاختبار بـ `Clock` قابل للحقن (لا `System.currentTimeMillis()` مباشر في المنطق).
3. رموز الطقس وأسماء الشهور الهجرية بالعربية.

### المسار E — طبقة البيانات والمصادر (`tools/` + القرار D1)

> **Zero-Network افتراضي.** لا يُسمح بأي طلب شبكة إلا بعد تفعيل المستخدم ل «الوضع المتصل» من الإعدادات، مع مؤشر واضح في كل رد.

1. `NetworkPolicy`: `OFFLINE_ONLY` (افتراضي) / `OPT_IN`. كل أداة تُعلن `requiresNetwork`؛ البوابة تمنع التنفيذ في الوضع الخطأ وتعيد رسالة: «المعلومة دي محتاجة اتصال — فعّل الوضع المتصل أو استخدم الحزمة المحلية».
2. `SourceEnvelope`: كل رد حقائقي يحتوي `text, sourceName, sourceUrl, license, fetchedAt, cached, confidence`. اعرض المصدر في `ChatScreen` كـ chip قابل للضغط (مثل المنافس).
3. `OpenMeteoClient` (CC BY 4.0) + geocoding للمدن المصرية/العربية (قائمة `CITIES` عند المنافس مرجع جيد)، و`WikipediaClient` عبر **Action API مع `origin=*`** (المسار الموثق للـ CORS)، و`WikidataClient` (SPARQL — اختبره فعليًا قبل الاعتماد عليه).
4. `SourceCache` (Room أو JSON مشفر): TTL لكل نوع (طقس 30 دقيقة، معلومات 30 يوم)، حد حجم، وزر «مسح الكاش».
5. **لقطات أوفلاين للقياس العادل:** `eval/fixtures/weather.json` و`eval/fixtures/facts.json` بقيم **مُتحقق منها**، تُستخدم في CI حتى لا نقيس «الرد جاب مصدر» بدل «الرد صح». هذا يصلح التحفظ المهم في تقرير المنافس.
6. **تشغيل الكود:** القرار D3 — في هذه المرحلة نكتفي بـ `CodeSnippets` (قصاصة + لغة + ناتج متوقع + تفسير سطر بسطر) من غير تنفيذ، مع ترك واجهة `CodeRunner` قابلة للتنفيذ لاحقًا. لا تضع WebView تنفّذ JavaScript عشوائي في النواة.
