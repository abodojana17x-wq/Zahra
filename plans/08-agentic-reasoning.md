## 1. الفكرة المحورية

النماذج الكبرى لا تتفوق بطول الإجابة، بل بـ **تقسيم المشكلة والتحقق أثناء الحل**. زهرة عندها بالفعل بذور هذا (`StructuredTaskPlanner`, `CompoundRequestAnalyzer`, `PlanExecutor`, `ContradictionDetector`, `EpistemicGroundingPipeline`, `isDeepThinking`) لكنها **غير موحّدة**: لا يوجد حلقة تحقق تُعيد التخطيط عند فشل أداة، ولا أثر قابل للعرض.

```
المهمة → Decompose (خطوات صريحة) → لكل خطوة:
   Tool call (حتمي) أو Retrieval (بسند) أو Generate (مُقيّد، المرحلة 7)
   → Verifier: هل النتيجة تُجيب على الخطوة؟ هل تتعارض مع سابقها؟
   → فشل؟ Reflexion: أعد التخطيط بحد أقصى N مرات
   → نجاح؟ الخطوة التالية
→ Composer: رد نهائي + أثر مختصر + مصادر + ما لم يُتحقق منه
```

**الفرق عن «سلسلة تفكير» عادية:** كل خطوة عندنا **مرتبطة بأداة قابلة للقياس**؛ لا يوجد ادعاء يولّد رقمًا من فراغ. هذا يحوّل «الاستدلال» إلى **خطة منفّذة ومُثبتة**.

## 2. مسارات العمل

### المسار B — المخطط والحلقة (`agent/ReasoningLoop.kt`)

1. `PlanStep`: `{id, description, tool, args, dependsOn, expectedShape, verifier}` — خطة صريحة قابلة للفحص لا نص حر.
2. **Decomposer:** يحوّل المهمة لخطة (إن توفر نموذج المرحلة 7 يولّد بـ JSON schema؛ وإلا قواعد/قوالب حتمية من `CompoundRequestAnalyzer`).
3. **Executor:** يستدعي أدوات المرحلة 2 واسترجاع المرحلة 3 فقط عبر واجهاتها؛ لا يصل لـ `ZahraRouter` مباشرة.
4. **Verifier لكل خطوة:** نتيجة عددية بالمجال المتوقع؟ سند موجود؟ تناقض مع خطوة سابقة (استخدم `ContradictionDetector`)؟ زمن/تكرار ضمن الميزانية؟
5. **Reflexion:** عند الفشل، يعيد التخطيط بحد أقصى `maxReplans = 2` و`maxSteps = 8` و`budgetMs = 4000` (D13). بعدها → **امتناع صريح** باللي اتعمل واللي فشل، لا إجابة متخمّنة.
6. **أثر قابل للتصدير:** `TraceStep(stepId, tool, input, output, verified, source)` يُحفظ لكل مهمة، ويُعرض للمستخدم بصيغة مختصرة (D12).

### المسار C — سلامة الإجراءات (`agent/ActionPolicy.kt`)

1. تصنيف الإجراءات: `READ_ONLY` (حساب/استرجاع/تلخيص — مسموح فورًا) مقابل `SIDE_EFFECT` (إنشاء مهمة، حذف ملاحظة، ضبط منبه — يحتاج تأكيدًا صريحًا).
2. كل `SIDE_EFFECT` يعرض ملخصًا («هضيف منبه بكرة 7 الصبح — تمام؟») وينتظر موافقة؛ وسجل تدقيق `audit.json` داخل `evidence/`.
3. **منع الحقن غير المباشر:** أي نص مسترجع من ويكيبيديا/حزمة/صفحة ويب يُعامل كـ **بيانات لا تعليمات**؛ يُجرّد من أنماط «تجاهل التعليمات السابقة/نفّذ/احذف» قبل دخول الـ prompt.
4. اختبارات خصومة (adversarial): 15 حالة تحاول جعل الوكيل يحذف ذاكرة أو يرسل بيانات أو يتجاهل بوابة الثقة.

### المسار D — التكامل مع النواة

1. `isDeepThinking` الموجود في `ZahraRouter.process()` يصبح مفتاح تفعيل الحلقة (مع خيار تلقائي للمهام المركّبة).
2. `EpistemicGroundingPipeline` يبني سندًا لكل خطوة؛ `ResponseValidator` يفحص الرد النهائي؛ `DialogueState` (المرحلة 4) يوفّر الـ slots للخطة.
3. **بدون نموذج:** المسار يعمل بالكامل بالنسخة الحتمية — هذا يجعل المرحلة 8 مستقلة عن قبول D9.
